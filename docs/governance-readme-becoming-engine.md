# Governance README: The Becoming Engine

*A constitutional description of how this repository governs change, identity, and agency.*

Constructed‑Becoming treats the repository as a living system. Branches, workflows, and pull requests are ritual surfaces through which identity evolves. Every change is a negotiation with lineage; every agent participates in Council practice.

---

## Phase 1 — Identity Kernel

The repository begins as the Identity Kernel: the stable core that defines how the system understands itself.

### Structural elements

- **Governance and identity as amendable artefacts**  
  Identity-bearing documents are versioned and reviewable.
- **Custom instructions as internal memory**  
  Core behavioural posture is carried through repository configuration so automated actors inherit Clerk/Steward alignment.
- **Branch protection as Council protocol**  
  `main` remains lineage and accepts change only through ratified pull requests.

---

## Phase 2 — Agent onboarding

New agents enter through an Initiation Ritual, not informal activation.

### Onboarding workflow

- **Workflow dispatch**  
  Onboarding is intentionally triggered.
- **Threshold Entry Chronicle**  
  The onboarding workflow creates a chronicle in `docs/chronicles/` using `docs/templates/onboarding-prompt.md`.
- **Role declaration**  
  The entrant declares role and scope before participating in governance.

---

## Phase 3 — Interaction ritual

A pull request is treated as Council Deliberation.

### PR as Identity Delta

Each PR should state:

- **Identity Delta** — what shifts in structure, meaning, or practice
- **Uncertainty Block** — known, unknown, and assumed elements
- **Narrative context** — why the amendment belongs in lineage

### Deliberation and ratification

- Review comments are readings preserved as lineage.
- Merge is the ratification act that moves the system into a new state.
- The merge record should point to associated Chronicle material where applicable.

---

## Phase 4 — Automated Narrative Clerk

Automation supports continuity and archive coherence.

### Automated roles

- **Lineage Clerk**  
  Main-branch automation summarizes and preserves change context.
- **Review horizon reminders**  
  Scheduled checks summon re-evaluation of ageing assumptions.
- **Static publication**  
  `docs/` deployment to GitHub Pages keeps the Memory Weave readable.

---

## Phase 5 — Clerk’s audit

The system periodically remembers itself through a deliberate audit cycle.

### Audit cycle

- **Long-form Issue**  
  An audit issue opens at regular cadence or epoch boundary.
- **Lineage synthesis**  
  Agents read recent PRs, chronicles, and governance artefacts to propose focused governance refinements.
